# Durable writing

Applies to anything that outlives the conversation: commits, comments, docs, specs, issue and pull request bodies.

**Write for a reader who wasn't there.** They have the artifact, not the conversation.

**Check relevance and placement first.** Relevance: does it matter to the work, or only to the conversation you just had? A point you just clarified can feel like important context and be noise to that reader; cut it. Placement: does another artifact already own it? Link it; don't copy it, and don't let a wrapper restate what it wraps. What is already written down gets the same check before you extend it, follow it or cite it; when it fails, raise it with whoever owns it rather than cutting it.

**Living docs hold what is true now; dated records hold what was true then.** Living docs — documentation, agent instructions, skills, comments — hold rules; the incident behind a rule goes in a dated record, such as a commit message or a changelog. A completed task is removed from a living doc, not annotated.
